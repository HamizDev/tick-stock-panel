# 1.1.2 更新说明（2026-11-08）

## 完整统计冷启动

- 指数、ETF 和复权因子精确聚合仅读取 `symbol` 与日期列，避免宽表 DuckDB 视图重复合并历史文件 schema。
- 日期范围改用 `os.scandir` 的目录项信息，减少 Windows 上逐个目录的额外属性查询。
- 文件体积扫描按目录分为最多 4 个 I/O worker，与表统计重叠执行；线程池在请求结束前回收，热缓存不创建预取线程。
- 保持原行数、覆盖标的数、交易日数和日期字段；兼容混合 `quote_ts` 列、空表、空值以及旧版 ETF/index 存储。
- 保留现有 Polars 并发闸。聚合后不持有行情 DataFrame，不额外落盘统计数据库。

## 缓存一致性

- 同表冷请求合并为一次读取，storage 统计也只执行一次扫描。
- 空结果同样缓存；同步失效时丢弃读取中的旧代结果，避免旧统计覆盖新数据。
- 继续先显示轻量概览，再显示完整统计；本次没有用近似计数替代原有精确聚合。

## 验证与测量范围

- 相同 Windows 机器及行情目录，修改前真实 `/api/data/status` 首次请求为 **7.446 秒**，第二次为 **3.8 毫秒**。
- 优化后真实首次请求 **2.342 秒**，下降约 **68.5%**；第二次 **2.0 毫秒**。首次请求时后台指标预热仍在运行。
- 精确聚合与各目录文件数/体积字段逐项核对一致；总存储量包含持续增长的运行日志，因此重启前后可有小幅变化。
- 本地版 **32 项**、公开版 **33 项**相关测试通过；新增 Ruff 问题为 0。两轮独立静态复核未发现 P1/P2，最终测试由主代理运行。
- 覆盖精确投影、混合 schema、null、空目录/空文件、旧存储回退、并发冷缓存、失效竞态、清理代次及首页初始化。
- 这里的“冷”指应用统计缓存为空，未清空操作系统文件缓存；耗时仍会受磁盘、其他后台任务和文件数量影响。

## 范围

- 公开版本仅包含统计性能与一致性修复、回归测试、版本元数据和更新说明。
- 不包含个人行情文件、自选、模拟账户、密钥、本地模型或预测结果；不改变分析策略和交易规则。
- 页面版本号通过后端接口更新，本次没有改动前端运行逻辑和构建资源。
